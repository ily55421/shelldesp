# 更新包路径检测修复：安装器自动定位已有安装（含免安装版）

- 日期: 2026-10-10
- 承接: `版本更新包-1.2.1-覆盖升级与数据保留-2026-10-10.md`
- 问题（用户反馈）: 更新包没有检测到已有的安装路径

## 一、核实结论（确认问题存在）

| 检查项 | 结果 |
|---|---|
| HKCU/HKLM 卸载注册项 | 无任何 ShellDesk 记录 |
| `HKCU\Software\{APP_GUID}\InstallLocation` | 不存在 |
| `%LOCALAPPDATA%\Programs\ShellDesk` | 不存在（从未用安装包装过） |
| 实际运行位置 | `E:\code\ai\shelldesp\dist\win-unpacked\ShellDesk.exe`（4 进程），桌面快捷方式也指向它 |

原因：用户一直运行的是**免安装（解压目录）版本**，它不会写 NSIS 注册表记录；NSIS 的"检测已有安装"完全依赖注册表 `InstallLocation`，所以向导只能给默认路径 `%LOCALAPPDATA%\Programs\ShellDesk`，无法覆盖用户实际在用的那份。

附加发现（会放大该问题）：electron-builder 的向导在安装前有"目录净化"逻辑（`app-builder-lib/templates/nsis/assistedInstaller.nsh:33-38`）——若所选目录**不含** `ShellDesk` 字样，会自动追加 `\ShellDesk`。因此即使用户在向导里手填 `...\dist\win-unpacked`，也会被改成 `...\dist\win-unpacked\ShellDesk`。

## 二、修复方案

1. **应用侧**（`electron/main/index.ts`）：打包后启动时把自身 exe 所在目录写入 `%APPDATA%\shelldesk\install-path.txt`（`recordInstallPath()`，仅 `app.isPackaged` 生效，dev 运行不写）。
2. **安装器侧**（新增 `build/installer.nsh`，经 `nsis.include` 引入）：`customInit` 宏（在 `.onInit` 中、`initMultiUser` 之后执行）
   - 先读注册表 `HKCU/HKLM ${INSTALL_REGISTRY_KEY}\InstallLocation`：有记录则沿用 electron-builder 标准升级逻辑，不干预；
   - 无记录时读 `install-path.txt`，去行尾换行/空白后校验 `ShellDesk.exe` 存在，命中则 `StrCpy $INSTDIR` → **原地覆盖更新**；
   - 文件缺失或目录无效 → 回退默认目录。
3. **关闭目录选择页**（`nsis.allowToChangeInstallationDirectory: false`）：既避免上述"追加 \ShellDesk"的净化逻辑破坏检测结果，也让安装流程变成"双击 → 安装 → 完成"，更适合更新包。

## 三、验证

1. **隔离单测**（用 electron-builder 缓存的 makensis 编译真实 `build/installer.nsh`，4 个场景）：

| 场景 | marker 内容 | 结果 `$INSTDIR` |
|---|---|---|
| A 应用写入的正常路径 | `E:\code\ai\shelldesp\dist\win-unpacked` | 同左 ✅ |
| B 带 CRLF 行尾 | 同上 + `\r\n` | 同左（已裁剪）✅ |
| C 指向不存在的目录 | `E:\not-exist-xyz-123` | `%LOCALAPPDATA%\Programs\ShellDesk`（回退）✅ |
| D 无 marker | — | 默认目录 ✅ |

2. **端到端实测**（沙箱目录模拟免安装位置，静默运行真实 `ShellDesk-1.2.1-setup.exe /S`）：
   - 安装位置 = marker 指向的沙箱目录（2054 个文件、`ShellDesk.exe` 180 MB、`resources/app/package.json` = 1.2.1）→ 检测生效 ✅
   - 静默卸载后：注册表卸载项残留 0、文件清空，而 `%APPDATA%\shelldesk\config\config.json` 仍在（3853 字节）→ 数据保留策略 ✅
   - 清理沙箱与临时脚本，重新启动用户的应用：4 进程、标题 `PowerShell 7 — ShellDesk`，`install-path.txt` 由应用自动写回 `E:\code\ai\shelldesp\dist\win-unpacked` ✅

## 四、使用说明与注意事项

- 现在双击 `dist\ShellDesk-1.2.1-setup.exe`：安装器会检测到 `E:\code\ai\shelldesp\dist\win-unpacked` 并**原地覆盖更新**；若应用正在运行，安装器会提示关闭（首次安装无注册表记录，走提示+关闭流程）。
- 首次这样安装后该目录会带上卸载器与注册表记录，后续升级由注册表自动识别（也可继续靠 `install-path.txt`）。
- 该目录若之后再被 `npm run package:win` 重建会被清空（连同卸载器），属预期；重建前请先关闭应用。
- 目录选择页已移除（原因见第二节第 3 点）；如需自定义安装目录，可临时改 `allowToChangeInstallationDirectory: true`，但此时免安装路径检测会被"追加 \ShellDesk"逻辑干扰。
