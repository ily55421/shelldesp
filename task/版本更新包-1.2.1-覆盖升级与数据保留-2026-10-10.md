# v1.2.1 版本更新包：NSIS 覆盖升级安装包（保留用户数据）

- 日期: 2026-10-10
- 版本: 1.2.0 → 1.2.1
- 目标: 产出可覆盖更新「当前正在运行」的 ShellDesk、且不丢用户数据的版本更新包

## 一、产物

| 产物 | 说明 |
|---|---|
| `dist/ShellDesk-1.2.1-setup.exe` (85.7 MB) | 安装包 / 覆盖升级包，元信息 `ProductName=ShellDesk` `FileVersion=1.2.1` |
| `dist/win-unpacked/` | 免安装版（用户此前一直在运行的形态，已就地更新到 1.2.1） |

## 二、改动清单

1. **版本号**：`package.json` / `package-lock.json` → 1.2.1（`npm version` 同步）；README 版本说明更新。
2. **electron-builder.yml**：新增 `nsis` 目标与配置
   - `oneClick: false`（向导式）+ `allowToChangeInstallationDirectory`：升级时自动带出原安装目录，可原地覆盖
   - `perMachine: false`：装到 `%LOCALAPPDATA%\Programs`，无需管理员权限
   - `artifactName: ShellDesk-${version}-setup.${ext}`、`installerIcon/uninstallerIcon` 用项目图标
   - `deleteAppDataOnUninstall: false`：卸载也保留 `%APPDATA%\shelldesk`
3. **打包命令**：`package:win` 与 `.github/workflows/ci.yml` 的 Package 步骤追加 `--publish never`
   —— 本机环境 `CI=true`，electron-builder 会尝试发布 GitHub Release 并因缺少 `GH_TOKEN` 而报错退出（此前只有 `dir` 目标不触发发布，新增 nsis 后暴露）。
4. **标题栏显示真实版本**：新增 `app:get-version` IPC（主进程 `app.getVersion()`，带 sender 校验）+ preload `api.app.getVersion` + `env.d.ts` 类型，`TitleBar.vue` 由硬编码 `v1.0` 改为真实版本号，便于确认更新是否生效。

## 三、覆盖升级与数据保留机制

- **appId 不变**（`com.shelldesk.app`）+ 同一安装器身份 → NSIS 识别已安装版本，直接覆盖同一目录（非并行安装）。
- **正在运行的实例**：electron-builder 的 NSIS 内置 `CHECK_APP_RUNNING`（`app-builder-lib/templates/nsis/include/allowOnlyOneInstallerInstance.nsh`）——升级场景静默 `taskkill` 正在运行的 `ShellDesk.exe` 后继续；首次安装则弹窗提示关闭。
- **数据不丢**：打包内 `resources/app/package.json` 的 `name` 仍为 `shelldesk`（`productName` 只影响 exe/快捷方式名），`app.getPath('userData')` 因此仍是 `%APPDATA%\shelldesk`，与升级前完全一致；安装器也不触碰该目录。

## 五、注意事项

- 安装包**未签名**（`signAndEditExecutable: false`），首次运行会有 SmartScreen 提示，需“更多信息 → 仍要运行”。
- **重建 `dist/win-unpacked` 前必须先关闭正在运行的 ShellDesk**：`electron-builder` 会先清空输出目录，文件被占用时会在清理中途失败（本次即因此删掉了 `chrome_*.pak` 两个文件，已重建恢复）。直接运行 `setup.exe` 则无此问题（安装器会自动关闭运行中实例）。
